The smoothest scroll animation is the one you delete

The symptom

A Selected Works page carried a vertical project timeline: era gradients, a rail that drew itself down as you scrolled, cards that revealed on entry, category filters. On scroll the page stuttered. Cards below the fold stayed blank until the reveal fired. The rail animation barely registered on desktop. The filter broke the layout. The dropdown failed on mobile.

What was on the page

Four behaviors, all scroll-driven. A gradient rail whose fill height was set from getBoundingClientRect on every scroll frame, throttled with requestAnimationFrame. Cards that started at opacity:0 with a translate offset, revealed by an IntersectionObserver — with a 2.5-second timer as a safety release so nothing stayed invisible. Era chips, nodes, and connector arms sampled from a green-to-red gradient. Category filters that faded cards out, then applied display:none.

First fix

The first repair was structural, not visual. The page scripts were rewritten as dependency-free vanilla JavaScript in four isolated modules — cards, reveal, rail, filter — each wrapped in its own guard, so one failing module could not blank the page. Real bugs got fixed along the way: an overflow:hidden that clipped timeline nodes, hover expansion that fired on touch and skipped card states, a filter that left the layout broken. The page worked. It still stuttered.

The question that fixed it

What if the timeline axis were fixed? That question deleted the problem instead of tuning it. Every scroll-driven behavior went: no scroll listeners, no IntersectionObserver, no reveal. The rail became one static full-height gradient. Every card rendered visible from the start. The page went from stuttered to clean by removing code, not adding it.

The pattern worth keeping

Scroll-driven effects charge their runtime cost exactly where the user is looking: mid-scroll. A fixed axis beats a clever one. When an animation exists to decorate scrolling, test the page with it deleted — if the page gets better, the animation was the bug.

Result

One script block. Plain JavaScript, no dependencies. Zero scroll handlers, zero observers. Cards expand on hover and tap, filters work, the timeline reads top to bottom. The smoothest scroll animation is the one you delete.
