The report was finished. Two hundred and twenty-three numbers, each one checked.
Then we added the most important section in it.
It was a short list, in plain sight, of everything the report had not done. Not buried at the back in small print. Not left for a careful reader to notice by its absence. Written down, in the report itself, under a heading that said exactly that: not computed.
A report that tells you where it stops is a report you can use. That sounds obvious. Building one taught me how much work it takes to make it true.

A number with an address

I build calculation tools for electrical work — the kind of software that works out how much fault current a piece of equipment will face, and whether that equipment is rated to survive it. The numbers matter. A duty that is too high for its rating is not a rounding problem. It is equipment asked to do a job it was never built for.
So when we put together a demonstration report on a sample system we use for testing, we set a rule before we wrote a line of it.
Every figure in the report had to carry its address.
Not just the value — where the value came from. Which source file. Which place in that file. Two hundred and twenty-three figures, and every one of them listed that way in a manifest that travels with the report. If a reader doubts a number, they do not have to trust me. They can walk to the address and look.
The program that builds the report, by the way, computes nothing. That was deliberate. It gathers figures that were already produced and already checked elsewhere, cites them, and seals the set. A reporter who also does the arithmetic is a reporter with two chances to be wrong and no way to tell which one happened.

The seal that someone else checked

When the report was assembled, we sealed it.
A seal, in this sense, is simple. You take a fingerprint of every file the report depends on — a long code that changes completely if even one character in a file changes — and you chain those fingerprints together into one final code. Change anything later, and the seal no longer matches. The report can prove it is the same report that was checked.
But a seal you compute yourself, and then announce yourself, proves very little. So the check was done a second time, by a separate pass that did not use the builder’s own printout. It recomputed every fingerprint from the files, rebuilt the chain, and compared the result.
All fourteen chained files matched. The recomputed seal matched the sealed one. Spot checks traced individual figures back to their sources and found them exact.
That is the difference between we sealed it and it is sealed. The first is a claim. The second is a claim that survived someone trying to redo it without help.

Four failures, printed first-class

Here is the part I am proudest of, and it is not the passes.
The report carries verdicts — for each checked selection, the duty it will face, the rating its source states, and the answer: adequate, or not adequate. Most selections passed. Four did not.
One fuse fell short by a small margin — and the report also carries the replacement selection, which passes by a wide one. One device in a control centre fell short. One panel failed on its own and passed only as part of a tested combination, which the report says in those words, because passes in combination and passes are not the same sentence. One ground device was asked for slightly more than its rating states — close enough that a careless report would have rounded it into a pass. This one prints the two numbers side by side and lets them say no.
An engine that only ever says adequate is worthless. Anyone can build a tool that agrees with itself. The whole point of checking a selection against a published rating is that sometimes the honest answer is this one fails — and a report that prints its failures in the same size type as its passes is a report whose passes you can believe.

What the report refused to claim

Then, the not-computed list.
The sample system’s own real equipment could not be given verdicts, because the rating sheet for that equipment was not in our hands on the machine doing the work — it sits elsewhere, and no rating was assumed to fill the gap. A duty figure without a sourced rating is a question, not a verdict, so the report computes the duties and stops there.
Two whole kinds of study were also named as not done: a second international method we have not built yet, and a class of unbalanced faults that belongs to a later stage. Both are real work. Neither is in this report. Saying so costs one short section. Not saying so would cost the reader their ability to know what they are holding.
And the proof status was printed the same way — the full battery of checks that passed, stated plainly, beside the honest remainder: a set of formal proof items still open, named as open. Not hidden, not rounded into essentially proven. Open means open.

The draft that taught the lesson twice

There is a smaller story inside this one, and it is the reason I trust the process.
The first generated draft of the report looked complete. It had every section. But when someone read it end to end — actually read it, the slow way — two blocks were found printing their raw placeholders instead of the values that belonged there. The machinery had assembled those blocks as plain text where it should have filled them in. Every automated check we had would have waved it through, because the structure was perfect. Only the reading caught it.
We fixed it, rebuilt the report, and sealed only the corrected version.
Then, weeks of habit paid off a second time. A routine scan across the project found a small corruption repeated in a handful of files — the same few letters replaced by a marker, in a data file, in the checker that reads it, and in a test, all corrupted identically. That is why every check had passed: the file and its examiners shared the same flaw, so nothing disagreed. We repaired every copy, proved the repairs changed nothing else, and ran the full validation again. It passed — this time with the flaw actually gone. Four of the report’s sealed inputs had changed, so the report was regenerated and sealed again, and the older test report, whose inputs held none of the flaw, reproduced its original seal exactly. A control that behaves exactly as predicted is quiet evidence the machinery is honest.

The habit worth stealing

Most reports are written to be believed. This one was written to be checked.
That is a different job. A report written to be believed polishes its claims. A report written to be checked gives every number an address, seals the set, lets an independent pass redo the seal, prints its failures beside its passes, and lists — in its own pages — everything it did not do.
If you produce numbers that other people act on, steal the last part first. It is the cheapest and the hardest. Cheap, because it is one short section. Hard, because you have to write down, where everyone can see it, exactly where your work stops.
A report that lists what it did not do is not a weaker report.
It is the only kind I would sign.
