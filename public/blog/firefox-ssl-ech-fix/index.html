Fixing a Firefox-only SSL error by switching off Cloudflare ECH

P.Eng. — 24+ years, safety-critical energy systems
2026-09-26 · Built with Muse
Firefox refused the site with SSL_ERROR_ECH_RETRY_WITHOUT_ECH while Chrome sailed through. The culprit was upstream of the server entirely.
The symptom
A site fronted by Cloudflare loaded fine in Chrome but Firefox threw SSL_ERROR_ECH_RETRY_WITHOUT_ECH. Same machine, same network. When one browser fails and another doesn't, the bug is almost always in what the failing browser insists on — not in the server.
What was actually happening
ECH — Encrypted Client Hello — lets the TLS handshake hide the hostname. Cloudflare publishes the ECH public keys in the domain's HTTPS DNS record, in an ech= parameter. Firefox reads that record and fails closed when the keys don't check out. Chrome is more forgiving.
Querying the HTTPS record over DNS-over-HTTPS told the story: the ech= value alternated between two different keys seconds apart. The edge was advertising inconsistent keys, and Firefox — correctly, from its point of view — refused to proceed.
Diagnose it in 30 seconds
Ask any DoH resolver for the HTTPS record and look at ech=:
# repeat a few times, seconds apart curl -s "https://cloudflare-dns.com/dns-query?name=example.com&type=HTTPS" \ -H "accept: application/dns-json" | grep -o 'ech=[^ ]*' | cut -c1-40
If the key prefix changes between queries, you've found it. If ech= is absent, ECH isn't advertised and something else is wrong.
The fix
On Cloudflare's free plan there is no dashboard toggle for ECH — but the API exposes it. The safe way through:
  • Create a one-time token scoped to the minimum: Zone → Zone Settings → Edit, limited to the single zone.
  • PATCH /zones/{zone_id}/settings/ech with {"value":"off"}, then read the setting back to confirm.
  • Re-run the DNS check until ech= is gone and stable.
  • Delete the token immediately. It did its one job.
Nothing else on the zone changes — not TLS versions, not DNS records, not Universal SSL. The only delta is that the edge stops advertising ECH keys.
The pattern worth stealing
One-time, least-privilege API tokens: create scoped to a single job, use once, delete right after. It turns a standing credential risk into a non-event. We use this shape for any account change that the dashboard won't let us make directly.
Result
Firefox loads the site cleanly. The whole fix was one API call and a deleted token — the diagnosis was the actual work.
