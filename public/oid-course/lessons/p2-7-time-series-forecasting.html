2.7 Time Series, State Space, and Forecasting

Bridge lesson — connecting OID core to AI, technology, and electrical systems

Why this matters for AI, technology, and electrical systems

This is the lesson where econometrics meets your home turf. The Kalman filter that econometricians use for unobserved-components models is the same Kalman filter you know from signal processing and control — same equations, different vocabulary. ARMA models are digital filters; spectral analysis is the Fourier transform; system identification is parameter estimation. This lesson teaches time-series econometrics bilingually: every econometric concept paired with its EE translation, so the two halves of your training reinforce each other instead of living in separate folders. By the end you will model nonstationary telemetry, filter noisy sensor streams, handle volatility clustering in traffic, and evaluate forecasts the way Diebold does — out of sample, under a proper loss function, with a statistical test.

Learning objectives

  • Test for and handle nonstationarity: unit roots, differencing, and cointegration with the Engle–Granger and Johansen procedures.
  • Specify and estimate ARMA/ARIMA models via the Box–Jenkins workflow, and translate between ARMA and digital-filter representations.
  • Cast a dynamic model in state-space form and run the Kalman filter and smoother, connecting it to signal-processing intuition.
  • Model volatility clustering with ARCH/GARCH and interpret the results for bursty systems data.
  • Compare competing forecasts with the Diebold–Mariano test and design honest out-of-sample evaluations.

Core content

Stationarity, Wold, and ARMA

A time series is covariance stationary if E[yt] = μ, Var(yt) = γ0, and Cov(yt, yt−h) = γh depend only on h — statistics frozen in time. The Wold decomposition says any covariance-stationary process is a deterministic component plus an infinite moving average of uncorrelated shocks, yt = Σj=0∞ ψjεt−j with Σψj2 < ∞: every stationary series is filtered white noise. The ARMA(p,q) model, yt = Σi=1p φiyt−i + εt + Σj=1q θjεt−j, is the parsimonious parametric version. EE translation: write it with the lag operator L as φ(L)yt = θ(L)εt; the transfer function H(z) = θ(z−1)/φ(z−1) is exactly a digital filter, AR terms are poles (feedback), MA terms are zeros (feedforward). Stationarity requires the AR roots outside the unit circle — poles inside the unit circle, the stability condition you already know. The Box–Jenkins workflow is identification (ACF/PACF patterns suggest p, q — an AR(p) has a PACF that cuts off after p, an MA(q) an ACF that cuts off after q), estimation (MLE), and diagnostic checking (residuals should be white noise; Ljung–Box test). For trending data, difference d times: ARIMA(p,d,q). One caution from experience: overdifferencing creates artificial MA structure — difference only what unit-root tests say needs differencing.

Unit roots and cointegration

A unit root — an AR root exactly on the unit circle, e.g., the random walk yt = yt−1 + εt — means shocks never decay: the series has no fixed mean to revert to, and its variance grows with t. Regressing one random walk on another produces spurious regression: R2 near 1 and "significant" t-statistics between completely unrelated series, because both inherit trends. The Dickey–Fuller test tests H0: unit root in Δyt = α + γyt−1 + … + εt (reject if γ̂ is sufficiently negative), with nonstandard critical values because under the null the estimator has a non-normal asymptotic distribution; Phillips–Perron is the nonparametric-robust variant. If series are I(1) (stationary after first differencing) but a linear combination is I(0), they are cointegrated: they share a common stochastic trend and can't drift apart forever. Engle–Granger: regress y on x, test the residuals for a unit root — stationary residuals mean cointegration. Johansen generalizes to systems via a vector error-correction model (VECM), ΔYt = ΠYt−1 + …, where the rank of Π is the number of cointegrating relations. Systems intuition: request rate and server count in an autoscaling group are each nonstationary, but their ratio (utilization) is stationary — that's cointegration, and the VECM's adjustment coefficients say how fast the system restores balance after a shock. Always test before modeling in levels; this is the time-series analogue of "check exogeneity first."

State space and the Kalman filter — in your language

The state-space representation splits the world into what evolves and what you see. State (transition) equation: αt = Tαt−1 + Rηt, ηt ∼ N(0, Q) — the hidden dynamics. Observation equation: yt = Zαt + εt, εt ∼ N(0, H) — noisy measurements of the state. EE translation: this is the plant-plus-sensor model from control theory; αt is the true system state (actual queue length, true clock offset), yt is what your instruments report. The Kalman filter recurses in two steps. Predict: αt|t−1 = Tαt−1|t−1, Pt|t−1 = TPt−1|t−1T′ + RQR′ — propagate the estimate and inflate uncertainty. Update: Kt = Pt|t−1Z′(ZPt|t−1Z′ + H)−1, αt|t = αt|t−1 + Kt(yt − Zαt|t−1), Pt|t = (I − KtZ)Pt|t−1 — the Kalman gain Kt optimally weights the new measurement against the prediction by their relative precisions: trust the sensor when H is small, trust the model when P is small. The filter is the MMSE estimator of the state given measurements — the dynamic analogue of the conditional expectation from Lesson 2.3. The smoother runs backward for the best estimate using all data; the likelihood comes free from the prediction errors, so parameters (T, Q, H) are estimated by MLE. Econometric uses: unobserved-components models (trend + cycle decomposition of a metric), time-varying parameter regressions (let βt evolve as a random walk — the state is the coefficient vector), missing data (skip the update step when yt is missing — the filter handles gaps natively), and regime switching. If you've implemented a Kalman filter for sensor fusion or tracking, you already know this machinery — the econometrics is just new applications.

Spectral analysis: the frequency-domain view

Every stationary series has a spectral density f(ω), the Fourier transform of its autocovariance sequence — the distribution of variance across frequencies. EE translation: it's the power spectral density; white noise is flat, an AR(1) with positive φ concentrates power at low frequencies (red noise — slow wandering, like datacenter temperature), and seasonal/daily patterns in telemetry appear as sharp peaks at the corresponding frequencies. Estimating the spectrum (periodogram, smoothed) is often the fastest diagnostic: a peak at ω = 2π/24 in hourly data screams "daily cycle" before any model is fit. The frequency domain also gives clean results — e.g., the spectrum of an ARMA is |θ(e−iω)|2/|φ(e−iω)|2 times the noise variance, the squared magnitude response of your digital filter. When telemetry shows strong periodicities (cron jobs, batch windows, diurnal load), model them in whichever domain is clearer — seasonal ARIMA in time, or explicit Fourier terms as regressors.

(G)ARCH: volatility clustering

Financial returns — and bursty systems telemetry — show volatility clustering: large changes follow large changes. Engle's ARCH: εt = σtzt, σt2 = ω + Σi=1q αiεt−i2 — today's variance depends on recent squared shocks. Bollerslev's GARCH(p,q) adds lagged variances: σt2 = ω + Σαiεt−i2 + Σβjσt−j2 — an ARMA for variance, and GARCH(1,1) fits most data shockingly well. Diagnose from squared residuals: if ε̂t2 is autocorrelated, you have ARCH effects. Applications beyond finance: packet-loss burstiness, error-rate volatility during incidents, traffic variance for capacity planning — anywhere the variance forecast matters as much as the mean (and for provisioning, it does). Estimation is by MLE; standardized residuals ε̂t/σ̂t should be i.i.d. — check them.

Forecast evaluation: Diebold–Mariano

In-sample fit is not forecasting ability. The honest protocol: split into estimation and evaluation windows (or use rolling/recursive origins), generate genuine out-of-sample forecasts, and compare under an explicit loss function L(e) — squared error, absolute error, or an asymmetric loss if over- and under-prediction cost differently (overprovisioning vs. SLA breach). The Diebold–Mariano test (1995) tests equal predictive accuracy: with loss differential dt = L(e1t) − L(e2t), DM = d̄/√(Var̂(d̄)) →d N(0,1), using HAC standard errors since multi-step forecast errors are serially correlated. It asks the right question — "is forecast A significantly better than forecast B out of sample?" — without assuming either model is true. Practical disciplines: never select the model on the evaluation window (that's the test set — touching it for selection is leakage); report the loss function alongside the winner, because rankings can flip across losses; and remember that a "significant" DM statistic on 20 observations is fragile — forecast comparison needs evaluation samples the way estimation needs data.

Worked examples

Example 1: ARIMA for datacenter power demand

Hourly power draw for a datacenter shows trend growth plus a strong daily cycle. Augmented Dickey–Fuller on levels: p = 0.42 (unit root not rejected); on first differences: p < 0.01. ACF/PACF of differenced data suggests AR(2) with daily seasonal AR(1): ARIMA(2,1,0)×(1,0,0)24. Fitted residuals pass Ljung–Box (p = 0.31) — white noise achieved. 24-hour-ahead forecasts feed the cooling-plant schedule. EE note: the seasonal AR term is a comb filter tuned to the daily frequency; the differencing is a high-pass that removes the trend pole at z = 1. Takeaway: test → difference → identify → check residuals; the spectrum would have shown the daily peak before any modeling.

Example 2: Kalman filter for clock synchronization

You need true clock offset between two servers from noisy NTP measurements arriving irregularly, some dropped. State: αt = [offset, drift]′, evolving as a random walk (drift nearly constant, offset integrates drift). Observation: yt = offset + noise when a measurement arrives.

from pykalman import KalmanFilter
kf = KalmanFilter(transition_matrices=T, observation_matrices=Z,
                  transition_covariance=Q, observation_covariance=H,
                  initial_state_mean=m0, initial_state_covariance=P0)
state_means, state_covs = kf.filter(y_masked)   # NaN = missing: update skipped
smooth_means, _ = kf.smooth(y_masked)

The filter bridges measurement gaps by propagating the drift model, and the smoother gives the best post-hoc offset estimates for correlating logs across machines. Parameters (Q, H) estimated by EM on a week of data. Takeaway: state space handles missing data, irregular sampling, and unobserved states in one framework — the sensor-fusion pattern applied to infrastructure.

Example 3: Cointegration in autoscaling

Per-minute request rate rt and active server count st are each I(1) (ADF p > 0.3). Engle–Granger: regress log st on log rt; ADF on residuals rejects the unit root (p = 0.02) — cointegrated, as expected: the autoscaler targets utilization. The VECM adjustment coefficient on the server equation is −0.35: 35% of a utilization gap closes per minute — the measured speed of your autoscaler. During an incident, the adjustment coefficient collapses toward zero: the error-correction mechanism broke (scaling API throttled), which the VECM detects in real time. Takeaway: cointegration formalizes "these move together"; the adjustment speed is a directly monitorable systems metric.

Example 4: Diebold–Mariano for capacity forecasts

Two models forecast next-day peak traffic: a seasonal ARIMA and a gradient-boosted tree on calendar features. Over 90 out-of-sample days with squared-error loss, d̄ = −0.18 (ARIMA better on average) with HAC standard error 0.07: DM = −2.57, significant at 1%. But under absolute-error loss, DM = −1.1 (not significant) — the ARIMA's edge comes from a few high-traffic days where the tree badly missed. Since capacity planning cares most about peaks (asymmetric loss penalizing underprediction), you adopt a weighted loss and re-test: ARIMA wins decisively. Takeaway: the loss function is a modeling choice that encodes costs — report it, and let it decide, not R2.

Key results to remember

  • Covariance stationarity + Wold decomposition: every stationary series is filtered white noise; ARMA is the parsimonious parametric filter, with AR roots outside the unit circle (poles inside — the stability condition).
  • Unit roots make shocks permanent and cause spurious regression; test with Dickey–Fuller/Phillips–Perron and difference. Cointegration (Engle–Granger, Johansen VECM) means nonstationary series share a trend; the adjustment coefficients measure reversion speed.
  • State space splits hidden dynamics (αt = Tαt−1 + Rηt) from noisy measurements (yt = Zαt + εt); the Kalman gain optimally weights prediction vs. measurement by relative precision. Handles missing data, time-varying parameters, and unobserved components natively.
  • The spectral density is the power spectrum: variance distributed across frequencies; periodicities in telemetry appear as peaks. ARMA's spectrum is the squared magnitude response of its digital filter.
  • GARCH models volatility clustering (variance as ARMA); diagnose via autocorrelated squared residuals. Forecast the variance when provisioning depends on it.
  • Diebold–Mariano tests equal out-of-sample predictive accuracy under an explicit loss function, with HAC standard errors. Evaluate out of sample, never select on the test window, and let the loss function encode real costs.
  • EE dictionary: ARMA = digital filter, Kalman filter = optimal state estimator, spectrum = PSD, system identification = parameter estimation, cointegration = balanced control loop.

Check your understanding

  1. Two trending telemetry series show R2 = 0.97 and highly significant t-statistics. Should you celebrate?
    Answer

    No — this is the signature of spurious regression. Test both for unit roots first; if both are I(1), the "relationship" is likely shared trends. Difference, or test for cointegration if you believe they genuinely move together.

  2. Your Kalman filter's estimates jump wildly with each new measurement. What does this tell you about your Q and H settings?
    Answer

    The Kalman gain is too high — you're over-trusting measurements relative to the model, i.e., H is set too small relative to Q (or P). Increase measurement-noise variance H (or decrease process noise Q) so the filter smooths rather than chases noise.

  3. Why must the Diebold–Mariano test use HAC standard errors rather than classical ones?
    Answer

    Multi-step-ahead forecast errors are serially correlated by construction (overlapping horizons), so the loss differentials dt are autocorrelated. Classical SEs would understate the variance of d̄; HAC standard errors account for the dependence.

  4. When would you prefer a state-space model over ARIMA for a telemetry series with missing observations?
    Answer

    State space handles missing data natively — the filter simply skips the update step and propagates the prediction, with uncertainty growing appropriately. ARIMA requires imputation or workarounds. State space also wins when you need unobserved components (trend/cycle split) or time-varying parameters.
