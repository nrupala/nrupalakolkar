7.6 Optimization Foundations

Doctoral course basis: Introduction to Optimization

Why this matters for AI, technology, and electrical systems

Every resource-allocation problem in networks and compute is an optimization problem: route flows to minimize latency (linear programming), allocate transmit power across subcarriers (convex optimization — water-filling is KKT in action), place data centers or schedule jobs on machines (integer programming), split a giant problem across regions (decomposition). OIDD 9120's static-optimization half gives you duality as a certificate of optimality and KKT as the working optimality condition — the same tools that train your neural networks and price your cloud capacity.

Learning objectives

  • State weak and strong LP duality and use complementary slackness to certify optimality.
  • Formulate integer programs and explain branch-and-bound, cutting planes, and Lagrangian relaxation.
  • Write KKT conditions for convex problems and state Slater's condition for strong duality.
  • Describe Dantzig–Wolfe and Benders decomposition and when each applies.
  • Match problem structure (LP / convex / integer / network) to the right solution paradigm.

Core content

Linear programming and duality

The primal LP: min cᵀx s.t. Ax ≥ b, x ≥ 0. Its dual: max bᵀy s.t. Aᵀy ≤ c, y ≥ 0. Weak duality: any feasible dual value ≤ any feasible primal value — every dual-feasible y is a certificate lower-bounding the optimum. Strong duality: at optimality the values are equal (when both are feasible). Complementary slackness: at optimal (x*, y*), y*_i(a_iᵀx* − b_i) = 0 and x*_j(c_j − a_jᵀy*) = 0 — a constraint with slack has zero dual price, and a positive variable has a tight dual constraint. Together these let you verify optimality without re-solving: exhibit primal- and dual-feasible points with equal values.

The dual variables are shadow prices: y*_i = ∂(optimal value)/∂b_i, the marginal value of relaxing constraint i — the economic content behind congestion pricing, and the reason dual solutions are often more interesting than primal ones. The simplex method walks vertices; interior-point methods follow the central path with polynomial-time guarantees and dominate large-scale practice.

Convex optimization and KKT

Minimize a convex f over a convex set: any local optimum is global — the single fact that makes convex optimization tractable. For min f(x) s.t. g_i(x) ≤ 0, h_j(x) = 0 with f, g_i convex and h_j affine, the KKT conditions are: stationarity (∇f + Σλ_i∇g_i + Σν_j∇h_j = 0), primal feasibility, dual feasibility (λ ≥ 0), complementary slackness (λ_i g_i = 0). Under a constraint qualification (e.g., Slater's condition: a strictly feasible point exists), KKT is necessary for optimality; with convexity it is also sufficient — so solving KKT is solving the problem. The Lagrangian dual g(λ,ν) = inf_x L(x,λ,ν) always lower-bounds the primal (weak duality); strong duality (zero gap) holds under Slater's condition.

Algorithms: gradient descent, Newton's method (using Hessians), and their stochastic variants — the same methods training ML models, now with convergence theory attached. SDP and QP formulations extend the reach to control (LQR), robust estimation, and combinatorial relaxations.

Integer programming: relaxations and cuts

Add integrality: min cᵀx s.t. Ax ≥ b, x ∈ ℤⁿ. The LP relaxation (drop integrality) gives a bound; branch-and-bound partitions on fractional variables, pruning by bound. Cutting planes / valid inequalities tighten the relaxation by cutting off fractional solutions without removing integer ones — the engine behind modern MIP solvers. Lagrangian relaxation moves complicating constraints into the objective with multipliers, decomposing the problem into easy subproblems and yielding bounds; column generation and branch-and-price handle exponentially many variables by generating them on demand; Benders decomposition projects out continuous subproblem variables, iterating between a master integer problem and dual-derived cuts.

Decomposition for large structured problems

Dantzig–Wolfe decomposition exploits block-angular structure (independent blocks + coupling constraints): the master problem coordinates via prices while subproblems solve independently — the optimization analogue of dual decomposition in distributed systems. Benders does the reverse, keeping complicating (integer) variables in the master. For an engineer: multi-region capacity planning, network design, and unit commitment in power systems all decompose this way, and the same price-coordination idea appears in TCP congestion control (dual decomposition of network utility maximization).

Networks: the combinatorial backbone

Shortest path, max flow / min cut, matching, facility location — network flow LPs are totally unimodular, so their LP optima are automatically integral: integer programming for free. Max-flow/min-cut duality is strong LP duality made concrete, and it is the workhorse behind distribution network design (Lesson 7.2) and survivable network topology.

Dual decomposition: TCP congestion control as optimization

Duality is not just a certificate — it is a distributed algorithm. Consider network utility maximization: max Σ_s U_s(x_s) s.t. Rx ≤ c (link capacities), x ≥ 0, with R the routing matrix. The Lagrangian L = Σ_s U_s(x_s) − Σ_l p_l((Rx)_l − c_l) separates by source given link prices p_l: each source solves max_{x_s} [U_s(x_s) − x_s Σ_{l∈route(s)} p_l], and each link updates its price by gradient ascent on the dual, p_l ← [p_l + α((Rx)_l − c_l)]⁺. This is exactly TCP congestion control: link prices are queueing delays / drop probabilities, sources adapt rates to observed congestion signals, and the network converges to the socially optimal allocation without any central coordinator. Kelly's framework shows AIMD-style protocols are solving a global convex program by dual decomposition — Lesson 7.6's mathematics running inside every router on the internet.

Worked examples

Example 1: Water-filling power allocation (KKT in action)

Allocate total power P across n subcarriers with channel gains g_i to maximize Σ log(1 + g_i p_i) s.t. Σ p_i = P, p_i ≥ 0. Lagrangian: L = Σ log(1+g_i p_i) − λ(Σ p_i − P) + Σ μ_i p_i. KKT stationarity: g_i/(1 + g_i p_i) − λ + μ_i = 0, with μ_i p_i = 0. Hence p_i = (1/λ − 1/g_i)⁺ — the water-filling solution: pour power where the channel is good, down to the "water level" 1/λ chosen so Σ p_i = P.

import numpy as np
g = np.array([0.5, 1.0, 2.0, 4.0]); P = 10.0
# bisection on water level mu = 1/lambda
lo, hi = 0.0, 1/min(g) + P
for _ in range(60):
    mu = (lo+hi)/2
    if np.sum(np.maximum(mu - 1/g, 0)) > P: hi = mu
    else: lo = mu
p = np.maximum(mu - 1/g, 0)
print("power:", p.round(3), " sum:", p.sum().round(6))
# -> [0. 1.25 2.75 6.0]: the weakest carrier gets nothing (KKT at work)

Example 2: Certifying LP optimality with complementary slackness

Primal: min 3x_1 + 5x_2 s.t. x_1 + x_2 ≥ 4, 2x_1 + x_2 ≥ 6, x ≥ 0. Dual: max 4y_1 + 6y_2 s.t. y_1 + 2y_2 ≤ 3, y_1 + y_2 ≤ 5, y ≥ 0. Candidate x* = (2, 2): primal value 16, both constraints tight. Dual candidate y* = (1, 1): constraints 3 ≤ 3, 2 ≤ 5; dual value 4 + 6 = 10 ≠ 16 — not optimal. Solve properly: dual optimum at intersection y_1 + 2y_2 = 3 with y_1 = 3 − 2y_2; value 4(3−2y_2) + 6y_2 = 12 − 2y_2, maximized at y_2 = 0 → y* = (3, 0), value 12. Then x*: complementary slackness with y*_2 = 0 leaves constraint 2 possibly slack; y*_1 = 3 > 0 forces x_1 + x_2 = 4; dual constraint 1 tight forces... solving gives x* = (4, 0), value 12 = dual value. Certificate complete: 12 is optimal.

Example 3: Facility location as integer programming

Choose data-center sites (binary y_j, fixed cost f_j) to serve demand regions (assignment x_{ij} ∈ {0,1}, transport cost c_{ij}): min Σ f_j y_j + Σ c_{ij} x_{ij} s.t. each region assigned, x_{ij} ≤ y_j (can't serve from an unopened site). The LP relaxation opens "fractional" sites; branch-and-bound branches on fractional y_j; valid inequalities (e.g., cover cuts) tighten the bound. Lagrangian relaxation of the assignment constraints decomposes into per-site subproblems — the standard approach for continental-scale network design.

Key results to remember

  • Weak duality: dual-feasible values bound the primal optimum — a certificate. Strong duality: the bound is tight for LPs.
  • Complementary slackness characterizes optimal primal–dual pairs; dual variables are shadow prices (marginal constraint values).
  • KKT (stationarity, primal/dual feasibility, complementary slackness) is necessary under constraint qualifications and sufficient under convexity.
  • Slater's condition (strict feasibility) ⇒ strong duality for convex problems — zero duality gap.
  • Integer programming: LP relaxation bounds, branch-and-bound partitions, cutting planes tighten, Lagrangian relaxation decomposes.
  • Dantzig–Wolfe (block-angular → price coordination) and Benders (complicating variables in master, cuts from subproblem duals) scale structured problems.
  • Network flow LPs are totally unimodular: integrality comes free; max-flow/min-cut is duality made concrete.
  • Match paradigm to structure: LP for linear flows, convex for smooth convex costs, IP for discrete choices, DP for sequential uncertainty.

Check your understanding

  1. In the water-filling example, why does the weakest subcarrier get zero power? Which KKT condition forces this?
    Answer

    p_i = (1/λ − 1/g_i)⁺: when 1/g_i exceeds the water level 1/λ, the unconstrained maximizer is negative, so the bound p_i ≥ 0 binds and complementary slackness (μ_i p_i = 0 with μ_i > 0) sets p_i = 0. Power goes only where marginal return exceeds λ.

  2. You have a primal-feasible x with value 12 and a dual-feasible y with value 12. What do you know?
    Answer

    Both are optimal: weak duality says dual ≤ primal always, so equal values certify optimality of both (strong duality realized at this pair).

  3. When would you choose Benders decomposition over Dantzig–Wolfe?
    Answer

    Benders when a small set of complicating variables (typically integers, e.g., facility-opening decisions) couples otherwise independent continuous subproblems — keep them in the master, generate cuts from subproblem duals. Dantzig–Wolfe when the structure is block-angular with coupling constraints across independent blocks.

  4. Why do network flow LPs not need integer programming machinery?
    Answer

    Total unimodularity of the node-arc incidence matrix: every basic feasible solution of the LP is integral when supplies/demands are integral, so the simplex optimum is automatically an integer flow.
