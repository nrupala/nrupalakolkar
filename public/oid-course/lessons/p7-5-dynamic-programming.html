7.5 Dynamic Programming and Stochastic Control

Built from Wharton OIDD 9340: Dynamic Programming and Stochastic Models

Why this matters for AI, technology, and electrical systems

Dynamic programming is the mathematics of sequential decisions under uncertainty — and it is also the mathematics underneath reinforcement learning, optimal power management, adaptive routing, and inventory control. Bellman's principle, contraction mappings, and structured policies are one coherent story: write the Bellman equation, prove the value function has structure, and read off the optimal policy's form before you ever compute. Lesson 7.7 will show that Q-learning is literally stochastic approximation applied to the Bellman equation you learn here.

Learning objectives

  • Formulate a sequential decision problem as a Bellman equation: states, actions, transitions, costs, horizon.
  • Write the finite-horizon, discounted, stochastic-shortest-path, and average-cost optimality equations.
  • Prove value-iteration convergence via the Banach fixed-point theorem applied to the Bellman operator.
  • Explain how K-convexity yields (s, S) optimality and how lattice methods yield monotone policies.
  • Compare value iteration, policy iteration, LP formulations, and approximate DP, including bandits and the Gittins index.

Core content

Bellman's principle of optimality

A Markov decision process has states s ∈ S, actions a ∈ A(s), transition probabilities P(s'|s,a), and one-step cost c(s,a). Bellman's principle: an optimal policy has the property that, whatever the initial state and decision, the remaining decisions are optimal for the state resulting from the first decision. This yields the optimality equations. Finite horizon (backward induction): V_t(s) = min_a [c(s,a) + E[V_{t+1}(s')|s,a]], V_T given. Discounted infinite horizon (β < 1): V(s) = min_a [c(s,a) + βE[V(s')|s,a]]. Stochastic shortest path: undiscounted with an absorbing zero-cost goal state, valid under proper policies. Average cost: g + h(s) = min_a [c(s,a) + E[h(s')|s,a]], where g is the optimal gain and h the bias — the right criterion for systems that run forever, like server farms and networks.

The discipline the course drills: state the state space, action space, transition law, and cost structure before touching any algorithm. Most failed DP formulations are failed state definitions — a state must be sufficient for the future, i.e., Markovian.

Contraction mappings: why value iteration converges

Define the Bellman operator (TV)(s) = min_a [c(s,a) + βE[V(s')|s,a]]. For discounted problems, T is a contraction in the sup norm: ‖TV − TW‖_∞ ≤ β‖V − W‖_∞. The Banach fixed-point theorem then gives everything at once: T has a unique fixed point V* (the optimal value function), and value iteration V_{k+1} = TV_k converges to V* geometrically at rate β from any start, with error bound ‖V_k − V*‖ ≤ β^k‖V_0 − V*‖. Policy iteration — alternate policy evaluation (solve linear equations) with policy improvement (greedy w.r.t. current V) — converges in finitely many steps for finite MDPs and typically far faster in practice. The LP formulation of discounted MDPs (maximize Σ α_s V(s) s.t. V(s) ≤ c(s,a) + βE[V|s,a]) shows DP and linear programming are dual views of the same object — a bridge to Lesson 7.6.

Structured policies: prove the form, then compute

The deepest part of OIDD 9340: optimal policies often have simple structure, and you can prove it. The exemplar is Scarf's K-convexity (1960): for the inventory DP with fixed order cost K, if the one-period cost is convex and the value function is K-convex — meaning f(x) ≤ ... precisely, f(θx + (1−θ)y) ≤ θf(x) + (1−θ)f(y) + θK in the relevant one-sided form — then K-convexity propagates through the Bellman recursion, and the minimizer of a K-convex function has the (s, S) form: order up to S iff inventory ≤ s. So (s, S) optimality is not an assumption — it is a theorem about shape preservation.

The general machinery is lattice programming (Topkis): if the DP's objective is submodular/supermodular in (state, action), the argmin is monotone in the state — yielding threshold and base-stock policies across inventory, queueing control, and replacement problems. Multimodularity extends this to multiple dimensions. The research strategy: hunt for structure before computing, because a structural result (base-stock, threshold, index policy) both explains and tames the problem.

Algorithms, approximation, and bandits

Exact methods (value/policy iteration, LP) die at large state spaces — the curse of dimensionality. Approximate DP / neuro-DP (Bertsekas Vol. II; Powell): approximate V with basis functions, fitted value iteration, temporal differences, and rollout policies. Q-learning (covered rigorously in Lesson 7.7) is stochastic approximation of the Bellman operator. Multi-armed bandits are the canonical exploration problem: the Gittins index (1979) reduces the Bayesian bandit to computing one index per arm and always playing the highest — an index policy proved optimal by an interchange argument, and the ancestor of UCB-style algorithms.

Average cost, Blackwell optimality, and the vanishing discount

For systems that run indefinitely — networks, server farms, power grids — discounting future costs at β < 1 is a modeling choice, not physics. The average-cost criterion minimizes long-run cost per stage g, with the Bellman equation g + h(s) = min_a[c(s,a) + E h(s')]. The standard route to it is the vanishing-discount approach: solve the discounted problem for β_n ↑ 1 and take limits; under recurrence conditions, (1−β)V_β(s) → g and V_β(s) − V_β(s_0) → h(s). A policy optimal for all β close enough to 1 is Blackwell optimal — the strongest infinite-horizon criterion, implying average-cost optimality. Practically: if your discounted solution is insensitive to β near 1, you have found the average-cost policy; if it flaps, your problem's long-run behavior genuinely depends on the horizon, and you should say so rather than pretend.

Worked examples

Example 1: Value iteration for a tiny inventory MDP

import numpy as np
S, Amax, beta = 6, 4, 0.9          # inventory states 0..5, order up to 4
demand = [0,1,2]; pd = [0.25,0.5,0.25]
h, p, c = 1.0, 5.0, 2.0            # holding, shortage, order cost (no fixed K)
V = np.zeros(S)
for _ in range(200):
    Vn = np.zeros(S)
    for s in range(S):
        best = np.inf
        for a in range(Amax+1-s):
            exp = sum(pd[d]*(h*max(s+a-d,0)+p*max(d-s-a,0)+V[min(max(s+a-d,0),S-1)]) for d in demand)
            best = min(best, c*a + beta*exp)
        Vn[s] = best
    V = Vn
S_star = int(np.argmax([-(c*a + beta*sum(pd[d]*(h*max(a-d,0)+p*max(d-a,0)) for d in demand)) for a in range(Amax+1)]))
print("V:", V.round(2), " approx base-stock S:", S_star)
# Without fixed K, the greedy policy is base-stock: order up to S every period.

Example 2: (s, S) emerges when K > 0

Add a fixed order cost K = 8 to Example 1's DP. Re-running value iteration, the optimal policy is no longer "order up to S always": from the computed policy table you read off s ≈ 1, S ≈ 4 — order 3–4 units only when inventory is 0 or 1, otherwise order nothing. The fixed cost makes small top-up orders uneconomical, batching replenishment exactly as Scarf's K-convexity theorem predicts. The structure was derived, not assumed.

Example 3: Server power management as stochastic DP

A server is idle or busy; when idle you may keep it awake (power cost 1/slot, zero wakeup delay) or sleep it (cost 0.1/slot, but a wakeup costs 5 and takes effect next slot). Jobs arrive as Bernoulli(0.3). States: (idle/busy) × (awake/asleep). The average-cost Bellman equation g + h(s) = min_a[c(s,a) + E h(s')] yields a threshold policy: sleep only if the expected idle run is long enough — a monotone policy provable by submodularity of the DP operator in (idle-time, action). This is the same mathematics as (s, S), applied to power instead of inventory.

Key results to remember

  • Bellman's principle yields four optimality equations: finite horizon, discounted (β<1), stochastic shortest path, average cost (g + h).
  • The Bellman operator T is a β-contraction in sup norm; Banach's theorem gives a unique V* and geometric convergence of value iteration.
  • Policy iteration converges finitely for finite MDPs and is usually faster; the LP formulation max ΣV s.t. V ≤ TV exposes DP–LP duality.
  • State the full MDP tuple (states, actions, transitions, costs) before any algorithm — a non-Markovian state is the most common formulation error.
  • K-convexity propagates through the inventory Bellman recursion ⇒ (s, S) optimality (Scarf 1960): the structured-policy exemplar.
  • Topkis lattice methods (submodularity/supermodularity, multimodularity) prove monotone/threshold optimal policies across control problems.
  • Curse of dimensionality ⇒ approximate DP, rollout, temporal differences; bandits ⇒ Gittins index policies for exploration.
  • Average-cost DP (g + h equation) is the right criterion for perpetually running systems: networks, server farms, power grids.

Check your understanding

  1. Write the discounted Bellman optimality equation and explain what each term means.
    Answer

    V(s) = min_a [c(s,a) + β E[V(s') | s,a]]. c(s,a) is the immediate cost of action a in state s; βE[V(s')] is the discounted expected optimal future cost from the random next state. Minimizing over a balances immediate vs. future cost.

  2. Why does the contraction property fail for undiscounted (β = 1) infinite-horizon problems, and what replaces it?
    Answer

    With β = 1, T need not be a contraction — value iteration may not converge and V* may be infinite. The stochastic-shortest-path framework (proper policies reaching an absorbing goal) or the average-cost formulation (g + h equation) replaces it.

  3. What does K-convexity buy you in the inventory DP?
    Answer

    K-convexity of the value function is preserved by the Bellman recursion, and the minimizer of a K-convex function has (s, S) form: there exist s ≤ S with "order up to S iff x ≤ s". Hence (s, S) policies are provably optimal with fixed order cost K.

  4. Your DP state is "last 3 demands". Is it Markovian? What could go wrong?
    Answer

    Only if the demand process's future depends on the past solely through the last 3 values (e.g., a 3rd-order Markov demand). If demand has longer memory or the cost depends on older history, the state is insufficient: the Bellman recursion optimizes the wrong problem and the "optimal" policy is suboptimal.
