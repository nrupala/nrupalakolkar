1.6 Modern Regression: Penalization, GLMs, GAMs

Doctoral course basis: Modern Regression for the Social, Behavioral and Biological Sciences

Why this matters for AI, technology, and electrical systems

Classical regression assumed n >> p and a correctly specified linear form. Modern engineering breaks both: you have 200 candidate telemetry features and 60 test runs (p > n), the response is a failure count or a bit-error probability (not Gaussian), and the true relationship is nonlinear in ways you can't guess. Penalized regression (ridge, lasso, elastic net) fits when predictors outnumber observations; GLMs handle binary and count data with the right likelihood; GAMs let each predictor contribute a smooth nonlinear curve. This is the bridge from the linear model to machine learning — and the source of most "my model looked great in training" disasters, which this lesson teaches you to avoid.

Learning objectives

  • Formulate ridge, lasso, and elastic-net estimators, explain the geometry that makes lasso sparse, and tune λ by cross-validation.
  • Choose among AIC, BIC, and cross-validation for model selection, matching the criterion to prediction vs. identification goals.
  • Specify and fit GLMs (logistic, Poisson) via IRLS, and diagnose overdispersion with quasi-likelihood.
  • Fit smoothing splines and GAMs, select smoothing parameters by cross-validation, and plot fits with uncertainty bands.
  • Explain why naive inference after model selection is invalid and name two honest remedies.

Core content

Penalized regression: ridge, lasso, elastic net

When p is large relative to n — or predictors are collinear — OLS is unstable or undefined. Penalized regression minimizes ‖y − Xβ‖² + λ·penalty(β). Ridge uses penalty Σβ_j² (L2): β̂_ridge = (X'X + λI)⁻¹X'y, shrinking all coefficients smoothly toward zero; it handles collinearity gracefully but keeps every variable. Lasso (Tibshirani 1996) uses Σ|β_j| (L1): the constraint region is a diamond whose corners sit on the axes, so the optimum lands exactly on axes — automatic variable selection, setting some coefficients to precisely zero. Geometry in one line: round constraint (ridge) touches the loss contours at interior points; pointy constraint (lasso) touches at corners.

Elastic net mixes both penalties, λ[αΣ|β_j| + (1−α)Σβ_j²]: lasso's sparsity plus ridge's grouping of correlated predictors (lasso alone picks one of a correlated pair arbitrarily — dangerous when the pair is "temperature at sensor A" and "temperature at sensor B"). The lasso has an oracle property under the irrepresentable condition: with proper λ it selects the true support and estimates as well as if the support were known. Tune λ by cross-validation (k-fold, minimizing out-of-fold error); the "one-standard-error rule" picks the simplest model within noise of the best — a cheap guard against overfitting. Always standardize predictors before penalizing (penalties are scale-dependent) and never penalize the intercept.

The lasso's degrees of freedom equal the expected number of nonzero coefficients (Zou-Hastie-Tibshirani) — a remarkably clean result that lets you build Cp/AIC-type criteria for penalized fits without extra simulation. And when predictors are grouped (dummy variables for one categorical factor, frequency bands of a spectrum), the group lasso penalizes whole groups in or out together, respecting the structure instead of shredding it.

Model selection: AIC, BIC, CV — and the post-selection trap

Three philosophies. AIC (−2ℓ̂ + 2p) estimates out-of-sample prediction error — asymptotically equivalent to leave-one-out CV for linear models. BIC (−2ℓ̂ + p log n) approximates the Bayes factor and is consistent: it finds the true model as n → ∞ (if truth is in the candidate set). Cross-validation directly estimates prediction error by refitting on folds — the most honest, most expensive. Match to goal: deploying a predictor → AIC/CV; claiming which effects exist → BIC.

The trap (Leeb & Pötscher; also lesson 1.5): after the lasso selects 7 of 200 features, the usual t-statistics on those 7 are computed as if you'd always meant those 7 — post-selection inference is invalid, p-values skewed toward significance. Honest remedies: sample splitting (select on half the data, do inference on the other half), selective inference (condition on the selection event; the Lee et al. truncated-Gaussian intervals for the lasso), or stability selection (keep features selected across many subsamples). In an engineering report, never present lasso-selected p-values without one of these.

One more practical subtlety: penalized fits are biased by design — the lasso shrinks even the true signals. The relaxed lasso (fit OLS on the selected support) or debiasing corrections recover honest coefficient magnitudes after selection. Report the penalized fit for prediction, but if engineering needs an unbiased effect size ("how many dB per volt, really?"), refit unpenalized on the selected variables — and remember the post-selection caveat still applies to its p-values.

GLMs and IRLS

Generalized linear models (McCullagh-Nelder) extend regression to non-Gaussian responses via three ingredients: a random component from an exponential family (binomial, Poisson, gamma...), a linear predictor η = Xβ, and a link function g(μ) = η connecting mean to predictor — logit for binary outcomes, log for counts. Fitting is by IRLS (iteratively reweighted least squares): linearize the score equations around the current fit, solve the resulting weighted least-squares problem, repeat — each iteration is just weighted OLS with working responses z and weights W from the current μ̂. It usually converges in under 10 iterations.

Diagnostics carry over with adjustments: deviance residuals replace raw residuals; the deviance D = 2(ℓ_saturated − ℓ̂) generalizes SSE with asymptotic χ² for nested-model comparison. Overdispersion — variance exceeding the family's (common: defect counts clump) — is handled by quasi-likelihood: keep the mean model, set Var = φ·V(μ), estimate the dispersion φ from Pearson residuals, and inflate standard errors by √φ̂. If φ̂ ≈ 3, your "significant" effects from the naive Poisson fit are roughly √3 too confident.

Splines and GAMs

When E[y|x] is nonlinear and unknown, smoothing splines minimize Σ(y_i − m(x_i))² + λ∫(m″)²dx — fit plus a roughness penalty; the solution is a natural cubic spline with knots at the data. λ chosen by cross-validation or GCV. Local polynomial regression (Fan-Gijbels) fits weighted polynomials in sliding windows — excellent at adapting to local curvature, weaker at boundaries (use local linear, not Nadaraya-Watson, to reduce boundary bias).

Generalized additive models (Hastie-Tibshirani) extend to many predictors: g(μ) = β_0 + Σ f_j(x_j), each f_j a smooth function fit by backfitting (iteratively smooth partial residuals). GAMs are the sweet spot engineers underuse: as flexible as you need per-variable, still interpretable per-variable — plot each f̂_j with its uncertainty band and read off "latency rises steeply with load past 70%, flat before." Choose smoothing parameters by CV/GCV, and always plot the fitted curves: a GAM you haven't looked at is a black box you chose by accident.

Worked examples

Example 1: Lasso selects 9 of 180 telemetry features

Predicting SSD failure within 90 days from 180 SMART telemetry features, n = 400 drives. Lasso with 10-fold CV: λ_min keeps 23 features (CV AUC 0.91); the one-SE rule keeps 9 (CV AUC 0.895) — nearly identical performance, far simpler model. Surviving: reallocated-sector count, temperature max, power-cycle count, six others. Correlated pairs (e.g., two temperature summaries) collapsed to one — elastic net (α = 0.5) instead keeps both with shared weight, which the hardware team prefers for redundancy. Then the honest step: the team wants p-values on the 9 features — refused; instead report CV performance and stability-selection frequencies across 100 subsamples (7 of 9 selected >80% of the time).

from sklearn.linear_model import LassoCV, ElasticNetCV
from sklearn.preprocessing import StandardScaler
Xs = StandardScaler().fit_transform(X)   # standardize BEFORE penalizing
lasso = LassoCV(cv=10).fit(Xs, y)        # tune lambda by 10-fold CV
print(lasso.alpha_, (lasso.coef_ != 0).sum())

Example 2: Ridge stabilizes a collinear calibration

Calibrating an RF power amplifier: output power regressed on 12 bias settings that move together (VIFs 8–40). OLS coefficients swing wildly — one bias gets +3.2 dB/V, its twin −2.9 dB/V, canceling. Ridge with λ chosen by CV shrinks both to +0.4 and +0.3 dB/V; prediction MSE on held-out boards drops 35%. The individual OLS coefficients were never identified (the data can't separate the twins); ridge's grouped shrinkage is the honest representation of that ignorance. Lesson: when predictors are near-duplicates, don't ask "which one matters" — ask "what does the group do."

Example 3: Logistic GLM for link failure, with overdispersion check

Modeling per-hour link failure (0/1) from temperature and humidity via logistic regression: logit(p) = β_0 + β_1·temp + β_2·humidity. IRLS converges in 5 iterations. β̂_1 = 0.31/°C (OR = e^{0.31} = 1.36 per °C — failure odds rise 36% per degree). Deviance residuals vs. fitted show no pattern; but failures cluster in storms — check overdispersion via grouped data: Pearson χ²/df = 2.4. Refit quasi-binomial: coefficients unchanged, SEs × √2.4 — the humidity effect drops below significance. Without the check you'd have shipped a false finding; quasi-likelihood is a two-line insurance policy.

Example 4: GAM for datacenter cooling

Predicting PUE (power usage effectiveness) from outside temperature, IT load, and humidity: PUE ~ s(temp) + s(load) + s(humidity). The fitted smooths show: PUE flat below 18 °C then rising steeply (free-cooling threshold — matches the chiller spec), decreasing convexly in IT load (fixed overhead amortized), humidity nearly flat. Each curve plotted with ±2 SE bands; the temp curve's kink at 18 °C is estimated ±1.5 °C. Smoothing parameters by GCV. The facilities team gets an interpretable model that a random forest couldn't give them — and the kink location becomes a design parameter for the next site.

Key results to remember

  • Ridge (L2) shrinks smoothly, handles collinearity; lasso (L1) gives exact zeros — sparsity from the diamond's corners; elastic net groups correlated predictors.
  • Tune λ by cross-validation; consider the one-SE rule. Standardize predictors first; never penalize the intercept.
  • AIC ≈ prediction (like leave-one-out CV); BIC ≈ consistent selection; CV directly estimates prediction error. Match criterion to goal.
  • Post-selection inference is invalid without adjustment — use sample splitting, selective inference, or stability selection before quoting p-values.
  • GLMs: exponential family + link (logit for binary, log for counts), fit by IRLS; deviance generalizes SSE; check overdispersion and use quasi-likelihood (SEs × √φ̂).
  • Smoothing splines / local polynomials / GAMs fit unknown nonlinearities; choose smoothness by CV/GCV; always plot each fitted curve with uncertainty bands.
  • Penalization, GLMs, and GAMs are Stein's phenomenon, exponential families, and smoothing made practical — the bridge from lesson 1.5 to machine learning.

Check your understanding

  1. Why does the lasso set coefficients to exactly zero while ridge only shrinks them?
    Answer

    The L1 constraint region is a diamond with corners on the axes; the elliptical loss contours typically first touch the diamond at a corner, where some coordinates are exactly zero. Ridge's spherical constraint touches at interior points with all coordinates nonzero (almost surely).

  2. You ran lasso on 500 features, kept 12, and a colleague reports their t-statistics as "highly significant." What's wrong, and what should you do?
    Answer

    Post-selection inference: the t-statistics ignore that the data chose those 12 features, so they're biased toward significance. Use sample splitting (infer on fresh data), selective-inference intervals, or report stability-selection frequencies and CV performance instead of p-values.

  3. Your Poisson regression of defect counts gives Pearson χ²/df = 4.1. Interpret and fix.
    Answer

    Severe overdispersion — variance is ~4× the Poisson assumption, so standard errors are ~2× too small. Refit with quasi-Poisson (inflate SEs by √4.1) or negative binomial, and look for unmodeled heterogeneity (e.g., batch effects) causing the clumping.

  4. When would you prefer a GAM over a random forest for an engineering model?
    Answer

    When you need per-variable interpretability — the GAM's plotted smooths show exactly how each predictor affects the response (e.g., locating a cooling threshold), while a random forest's effect is buried in interactions. GAMs also extrapolate more sanely and need less data per dimension.

  5. Two temperature features correlate at r = 0.97. Lasso keeps one, elastic net keeps both. Which behavior do you want for a safety-critical sensor model, and why?
    Answer

    Elastic net's: if the kept sensor fails or drifts, the lasso model has no backup and its coefficient was fit assuming the other was absent. Keeping both with shared weight is more robust — the "which one" question was never answerable from the data anyway.
